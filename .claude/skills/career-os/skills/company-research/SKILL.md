# 회사 조사

관심 회사가 어떤 사업을 하는지 알아보기 위해 공식 회사 자료와 DART 원문을 찾아 읽는다. JD·채용 법인·직무가 없어도 조사한다.
먼저 [공통 실행 계약](../../references/runtime-contract.md)을 읽는다.
이 파일을 읽은 뒤 CUA로 탐색하며, 검색 요약을 읽은 일을 브라우저 수행으로 세지 않는다.

## 입력

- 확인한 회사명, 알려진 공식 주소, 받은 사업·제품·고객 등의 관심 질문. 질문이 없으면 회사의 주요 사업부터 조사한다.
- 선택 보완 입력: 보고 기간, 선택 JD의 원문 URL·채용 법인·직무와 확인 시각. 미제공 값을 추정하거나 JD 제출을 조사 조건으로 삼지 않는다.
- 저장할 경로, 지난 결과, 공용 브라우저 소유권.

## 절차

1. 회사명·공식 주소로 조사 대상을 확인하고 공식 회사 소개에서 사업과 법인을 읽는다. 브랜드·관계사·공시 법인을 구분하며 모회사의 자료로 자회사 사실을 단정하지 않는다. 대상 자체가 모호할 때만 구분 질문을 한다. 채용 법인은 JD 미제공이면 미확인으로 남긴다.
2. CUA로 DART를 열어 회사명을 검색하고 조사 대상과 공시 법인의 관계를 확인한다. 이미 열린 탭을 재사용한다.
3. 사업·반기·분기보고서와 정정 여부를 확인하고 실제 보고서명을 그대로 기록한다.
4. 해당 보고서의 기간과 발행·제출일을 읽는다. 최근 제출 자료가 최신 사업 기간인지도 구분한다.
5. 받은 관심 질문 또는 주요 사업과 관련된 원문을 열고 항목명·쪽수·문단·URL 등 다시 찾을 위치를 남긴다.
6. 회사 사실과 관심 질문에 대한 해석을 분리해 적는다. JD가 있으면 직무 연결 해석을 추가한다. 공시로 현재 채용 이유를 단정하지 않는다.
7. 질문에 도움이 되는 근거와 남은 확인 사항을 짧게 반환하고 결과를 저장한다.

## JD 이후 채용 법인 보완

총괄이 `task=company`에 `company_supplement_required`와 선택 JD·기존 회사 결과를 전달하면, 채용 법인을 조사 대상으로 별도 보완한다. 기존 회사의 사업·수치·보고서를 새 법인 사실로 복사하지 않는다. 입력의 조사 법인과 새 채용 법인, 관계 근거, 실제 읽은 공식 출처·보고서 범위·미열람을 비교해 반환한다.

기존 `02-company.md`를 덮어쓰지 않고 새 revision의 별도 `02-company-supplement.md`에 기존 결과 참조와 선택 JD 참조를 붙인다. 보완이 막히거나 법인 관계가 미확인이면 그 상태를 반환한다. 경험 담당 호출과 진행 상태 변경은 총괄이 맡는다.

## 법인·보고서 확인

- 동명이인 법인, 변경 전 회사명, 관계사 자료가 아닌지 확인한다.
- 공고의 계약 법인이 미열람이면 브랜드와 DART 법인의 연결은 후보이며 동일 법인 확정으로 쓰지 않는다.
- 감사보고서는 감사보고서다. 사업보고서로 바꿔 부르지 않는다.
- 감사보고서만 확인했다면 그 범위와 한계를 남기고 사업 내용을 읽었다고 과장하지 않는다.
- 표·수치는 값, 단위, 기간, 연결·별도 범위와 지표 명칭을 함께 보존한다.
- 숫자가 없어도 질문에 답하는 사업 근거가 있으면 결과로 남긴다.
- 목록 0건은 로딩·필터·기간·법인 검색을 점검한 뒤 판단한다.
- 정정 보고서가 있으면 적용한 버전과 대체된 원문을 구분한다.

## 작은 출력

| 항목 | 남길 내용 |
|---|---|
| 대상 | 조사 회사·브랜드·조사 법인·공시 법인과 관계 근거. 채용 법인은 JD 미제공이면 미확인 |
| 자료 | 공식 소개·IR·공시 등 출처 종류, 실제 보고서명·종류, 보고 기간, 제출일, 정정 여부, 연결·별도 범위, 원문 URL |
| 사실 | 질문에 필요한 사업 사실과 원문 위치 |
| 해석 | 관심 질문에 대한 해석과 이유·확인할 점. 직무 연결은 JD가 있을 때만 |
| 범위 | 읽은 항목·미열람 항목, 실행 상태, 확인 시각 |

핵심 사실과 해석을 먼저 보여주고 긴 발췌는 만들지 않는다.
저장 경로를 받았으면 그 경로에 `02-company.md`를 저장하고 다른 담당의 결과를 덮어쓰지 않는다. 명시한 결과 파일명이 있으면 그 이름을 따른다. 실제 결과 위치·읽은 출처·미열람·남은 질문·업무 상태·필요 조치를 반환한다.
허용된 합성·지정 파일만 읽는 실행에서는 그 파일을 실제로 읽고 판독한 범위를 보고한다. 합성 조회 기록의 시각을 실시간 관측 시각으로 바꾸거나 파일 판독을 CUA·실제 DART 열람으로 기록하지 않는다.

## 중단과 대체·재개

- 조사 대상 법인이 모호해 자료를 연결할 수 없으면 구분이 필요한 상태로 반환한다. 채용 법인 미확인은 회사 조사를 막지 않는다. 후속 JD의 채용 법인이 다르면 그 법인 근거를 별도 보완하고 기존 회사 결과와 구분한다.
- 로그인·CAPTCHA·접근 차단은 원문 없음과 구분한다. 같은 원인은 최대 두 번 재시도한다.
- 정상 응답 0건은 관측 시각·법인·조회 기간·필터·점검한 범위를 남기고 그 조회 범위의 0건으로 표현한다. 전체 자료 부재로 확대하지 않는다. 공식 IR·사업 소개를 대안으로 읽고 출처 종류를 명시한다.
- 접속 시간 초과·결과 미표시는 조회 `blocked`, 원문 미열람으로 남기고 0건·자료 없음으로 단정하지 않는다. 재시도·필요한 접근 조치와 공식 IR·회사 소개 등 가능한 대안을 알린다. 대안도 못 읽었으면 미열람으로 남긴다.
- 대체 공식 자료를 읽은 것을 DART 사업보고서 탐색 성공으로 기록하지 않는다. 확인한 공식 소개 범위의 완료와 DART 미열람·차단 상태를 구분한다.
- CUA가 없으면 computer use 미실행으로 남기고 수행한 다른 조사만 구분해 보고한다.
- 재개할 때 법인·질문·보고서 버전을 확인하고 미열람 원문부터 이어 간다.
