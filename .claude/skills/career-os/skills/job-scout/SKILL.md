# 공고 찾기

학생이 공고를 미리 모으지 않아도 조건으로 실제 후보를 찾는다.
먼저 [공통 실행 계약](../../references/runtime-contract.md)을 읽고, 사용 가능한 computer use 도구로 실행한다.
파일을 읽거나 절차를 설명한 것만으로 실행 완료라고 기록하지 않는다.

## 입력

- 확인 회사와 실제 회사 결과 `02-company.md` 참조, 이미 받은 관심 업무·조건. 회사 결과를 먼저 읽고 조사 법인을 기준으로 비교한다.
- 지역·경력·필수 조건·후보 수·제외 조건은 받은 값만 재사용한다. 미지정 조건은 미지정이며 사용자 조건으로 추정하지 않는다.
- 저장할 경로와 지난 결과. 회사 결과가 없으면 총괄에 회사 선행 조사를 요청한다.
- 공용 브라우저의 현재 소유자. 조사 담당이 소유권을 받은 뒤 조작한다.

## 절차

1. 회사 결과·기존 조건을 읽는다. 업무가 없어 탐색을 좁힐 수 없을 때만 필요한 한 질문을 하고 턴을 끝낸다. 지역·경력이 미지정이어도 시작할 수 있다. 실제 사용할 브라우저를 확인한다.
2. CUA로 채용 사이트를 열어 검색·필터·목록 이동을 수행한다. 검색 답변으로 이 단계를 대체하지 않는다.
3. 후보의 공고 본문을 열고 실제 채용 법인과 직무, 경력·지역·필수·우대 조건을 읽는다.
4. 게시일, 마감일 또는 상시 모집 문구, 현재 모집 표시와 확인 시각을 기록한다.
5. 목록이 비었으면 로딩·필터·페이지 이동 여부를 확인하고 조건을 다시 확인한다.
6. 원문을 읽은 후보를 조건과 대조한다. 일부만 읽었으면 읽은 범위와 미열람 범위를 구분한다.
7. 학생이 고를 수 있게 후보와 차이를 짧게 반환하고 `03-jd.md`에 후보를 저장한다. 선택 질문 뒤 턴을 끝내며 선택 전에는 경험 담당을 호출하지 않는다.
8. 선택 답변을 받으면 선택 JD·선택 답변·채용 법인 비교를 새 결과 버전에 저장한다. 이미 공고를 지정한 입력은 선택으로 재사용한다.
9. 조건을 바꿔 다시 요청받으면 달라진 조건으로 재탐색하고 이전 후보의 상태도 다시 확인한다.

## 판정 기준

- 검색 결과 미리보기·추천 카드만 본 후보는 원문 확인 후보로 세지 않는다.
- 브랜드명과 고용 법인이 다르면 둘 다 적고, 법인을 모르면 확인 필요로 남긴다. 공식 채용 포털·브랜드 표기만으로 법적 채용주체의 동일성을 확정하지 않는다. 고용 법인이 명시된 근거가 없으면 후보에서는 확인 필요로 남기고 선택 후에는 `company_supplement_required`로 반환한다.
- 마감이 지났거나 모집 종료 표시가 있으면 현재 지원 가능한 공고로 제시하지 않는다.
- 공고 본문을 열었어도 최신 모집 여부를 알 수 없으면 상태는 미확인이다.
- 원문에 없는 보상·자격·직무 내용을 보태거나 우대 조건을 필수로 바꾸지 않는다.
- 로딩 실패·로그인·검색 차단을 공고 없음으로 바꾸지 않는다.

## 작은 출력

먼저 조건과 후보 차이를 짧게 보여주고 상세 근거는 저장한 결과에 둔다.

| 항목 | 남길 내용 |
|---|---|
| 실행 | 상태, 사용한 브라우저, 실제 수행한 탐색, 확인 시각 |
| 후보 | 공고 제목, 채용 법인, 직무, 조건 적합·차이, 현재 모집 상태 |
| 출처 | 실제 원문 URL, 마감 문구, 본문 위치, 읽은 범위·미열람 |
| 다음 | 학생의 선택 대기 또는 입력에서 이미 지정한 공고 |

저장 경로를 받았으면 공통 계약의 버전 규칙으로 `03-jd.md`를 저장한다. 후보와 선택 후 결과 모두 실제 결과 위치를 반환하고 다른 담당의 결과를 덮어쓰지 않는다.
채용 법인이 회사 결과의 조사 법인과 다르거나 연결이 미확인이면 `company_supplement_required`로 총괄에 반환한다. 브랜드·기존 조사 법인·채용 법인, 선택 JD 원문·확인 시각, 필요한 보완 질문을 포함한다. JD 담당이 회사 보완을 대신 완료하거나 경험을 호출하지 않는다. 총괄이 보완 파일을 읽은 참조를 반환한 뒤 그 참조를 선택 JD 결과에 붙인다.
후보 수는 입력을 따르며, 충분히 확인한 후보가 적으면 수를 채우려고 만들지 않는다.

## 중단과 재개

- 로그인·CAPTCHA는 사람의 인증이 필요하다고 반환하고 해당 탐색을 멈춘다.
- 같은 원인의 실패는 최대 두 번 재시도하고 실패 URL·증상·남은 작업을 저장한다.
- CUA가 없으면 computer use 미실행으로 남긴다. 웹 검색 성공으로 바꿔 기록하지 않는다.
- 조건에 맞는 공고가 없으면 검색 회사·조건·확인한 목록과 원문·미열람 범위를 남기고 `awaiting_user`로 회사 또는 조건 변경 선택을 기다린다. 접근 실패는 `blocked`·미열람으로 구분하고 재시도·접근 조치·다른 공개 출처 중 선택을 기다린다. 어느 경우에도 경험으로 자동 진입하지 않는다.
- 허용된 지정 파일 판독 모드는 해당 원문을 실제 읽고 합성 관측 시각을 보존한다. 파일 판독을 CUA 실행·실시간 모집 확인으로 기록하지 않는다.
- 재개할 때 마지막 결과·조건·모집 상태를 확인하고 실패한 탐색부터 이어 간다.
- 지원 버튼을 통한 실제 제출은 수행하지 않는다.
