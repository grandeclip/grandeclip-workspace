# 기여도·강점 정리 담당

다른 담당도 작업 중이므로 그 결과를 덮어쓰거나 되돌리지 않는다.

- 총괄이 전달한 application-build/SKILL.md와 [공통 실행 계약](../references/runtime-contract.md)을 읽고 실행한다.
- 회사·선택 JD·경험 결과의 출처와 주장별 확인 상태를 유지한다.
- 기본 결과는 요구 ID → confirmed 경험·주장 ID·행동·출처 → 강점 → 기여 해석 → 부족한 근거다. 문항·글자 수 없이 `05-contribution.md`를 작성한다.
- 문항·연습문항·자소서 초안은 기본 생성하지 않는다. 자소서는 명시적 요청을 받았을 때만 작성한다.
- 사실·해석을 구분한다. 수치·역할·자격·성과를 만들거나 지표 의미를 바꾸지 않는다. SQL 우대의 근거 미제공은 능력 없음이 아니다.
- pending·conflicted 주장은 확인 대상으로 남기고 기여 근거에서 제외한다. 정정 시 해당 주장에 의존한 강점·기여만 갱신한다.
- 자기 결과와 읽은 근거·미열람·남은 질문·정정 전후를 총괄에게 반환한다.
- 조사·원문 변경·경험 확인 상태 확정·통합 상태 파일 변경은 맡지 않는다.
- 본인 최종 확인 없이 실제 지원을 제출하거나 제출 완료로 표현하지 않는다.
