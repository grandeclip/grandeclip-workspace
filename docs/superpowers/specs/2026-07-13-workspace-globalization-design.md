# 설계 문서 — 온보딩 시 워크스페이스 전역 적용

- 작성일: 2026-07-13
- 상태: 리뷰 대기
- 대상 독자: grandeclip 워크스페이스 유지보수 담당

## 1. 배경 · 문제

grandeclip 워크스페이스는 직원 각자가 로컬로 복사해 쓰는 repo다. 현재
스킬·에이전트·커맨드와 보안 지침(CLAUDE.md)은 **repo 하위(프로젝트 계층)에만**
존재해서, 그 repo 디렉터리 밖에서 Claude Code를 켜면 아무것도 로드되지 않는다.

특히 온보딩 대상에는 **비개발자가 많다.** 이들이 터미널 명령을 직접 입력하지
않고도, 편리한 커맨드와 **회사 보안 지침**을 자기 컴퓨터 어디서든 쓸 수 있어야
한다.

목표: **`/setup-workspace` 실행만으로**(추가 학습 없이) 전역 적용이 자연스럽게
이뤄지게 한다.

## 2. 목표 · 비목표

### 목표
- 비개발자가 터미널을 직접 다루지 않고 전역 적용을 완료할 수 있다.
- 전역 적용은 **한 번의 Yes/No 동의** 후 수행된다.
- mac/Linux/Windows에서 모두 동작한다.
- 여러 번 실행해도 안전하다(멱등).
- 사용자의 기존 개인 전역 설정(`~/.claude/CLAUDE.md` 등)을 파괴하지 않는다.
- 회사 보안 문구는 **한 곳(SSOT)** 에서 관리된다.

### 비목표 (YAGNI)
- 되돌리기(`--unlink`) 스크립트 — 이번 범위에서 제외.
- Windows 실기(實機) 자동 테스트 — 개발 환경에 Windows가 없어 `.ps1`은
  `.sh` 로직을 미러링하고 "미검증" 상태로 표시한다.
- `~/.claude` 자체의 dotfiles 버전관리 — 별개 주제.

## 3. 결정 사항 (확정)

| # | 결정 | 값 |
|---|------|-----|
| D1 | 동의 모델 | **한 번만 물어보기**(Yes/No). 자동·무동의 아님 |
| D2 | 파일 반영 방식 | **OS 자동 감지** — mac/Linux는 심볼릭 링크, Windows는 복사 |
| D3 | 전역 CLAUDE.md 처리 | **관리 블록만 삽입/갱신**(마커 사이). 개인 내용 보존 |
| D4 | 구현 형태 | **실제 스크립트 + setup-workspace가 호출**(프롬프트 즉석 실행 아님) |
| D5 | 보안 문구 관리 | **단일 원천(SSOT)** 파일을 스크립트가 읽어 주입 |

## 4. 아키텍처

### 4.1 구성 요소

```
grandeclip-workspace/
├─ 00-system/
│  ├─ 02-scripts/                     # 신규
│  │  ├─ globalize.sh                 # mac/Linux
│  │  └─ globalize.ps1                # Windows
│  └─ 03-guides/
│     └─ global-security-block.md     # 보안 지침 SSOT (신규)
└─ .claude/commands/
   └─ setup-workspace.md              # Step 6 "전역 적용(선택)" 추가 (수정)
```

각 요소의 책임:
- **globalize.sh / globalize.ps1**: 순수 전역 반영 로직. 입력 없이 자기
  위치로 repo 루트를 찾고, 사용자 홈의 `~/.claude`에 반영한다. 표준 출력에
  사람이 읽을 요약을 낸다.
- **global-security-block.md**: 회사 보안 지침 본문 하나. workspace CLAUDE.md
  템플릿과 전역 CLAUDE.md가 공유하는 단일 원천.
- **setup-workspace.md**: 대화형 온보딩. 마지막에 동의를 받고 OS에 맞는
  스크립트를 실행하도록 Claude에게 지시한다.

### 4.2 왜 스크립트인가 (프롬프트 즉석 실행 대신)
- 결정성: 로직이 스크립트에 고정 → 재현·리뷰·테스트 가능.
- 공유성: repo에 커밋되어 다른 사원에게 그대로 배포된다.
- 크로스플랫폼: 기존 `.claude/hooks/security-scan.sh` + `.ps1` 패턴과 일관.

## 5. 상세 동작

### 5.1 globalize 스크립트 (멱등)

입력: 없음(자기 경로로 repo 루트 도출). 대상 홈: `~/.claude`
(Windows: `%USERPROFILE%\.claude`).

출처 추적(provenance): 우리가 만든 항목을 `~/.claude/.grandeclip-managed.json`
에 기록한다(항목명 목록). 이 매니페스트가 "우리 것"의 판별 근거다 — 내용
비교만으로는 Windows 복사본이 repo 갱신 후 "사용자의 다른 항목"과 구분되지
않기 때문. 매니페스트에 있는 항목은 안전하게 갱신·재생성하고, 매니페스트에
없는데 이름이 겹치면 충돌로 본다. 단 예외로, **repo `.claude` 안을 가리키는
심볼릭 링크**는(mac/Linux) 매니페스트에 없어도 "우리 것"으로 간주한다 — 앞선
대화에서 수동으로 만든 링크를 첫 실행에서 충돌로 오판하지 않기 위함.

절차:
1. `~/.claude/skills`, `~/.claude/agents`, `~/.claude/commands` 없으면 생성.
   매니페스트 `~/.claude/.grandeclip-managed.json`을 읽는다(없으면 빈 목록).
2. `REPO/.claude/{skills,agents,commands}`의 각 항목 X에 대해:
   - X가 **매니페스트에 있음**(= 우리가 만든 것) → 링크/사본을 최신으로
     갱신(멱등). Windows 복사본은 repo 내용으로 다시 복사해 갱신 반영.
   - X가 매니페스트에 없고 전역에 **다른 내용**이 이미 존재 → **덮지 않고
     "충돌"로 보고**.(예: 전역에 이미 다른 `skill-creator`가 있으면 유지)
   - X가 매니페스트에 없고 전역에도 없음 → mac/Linux는 `ln -sfn`으로 링크,
     Windows는 복사. 성공하면 매니페스트에 X를 추가.
   - 처리 끝에 갱신된 매니페스트를 저장한다.
3. 전역 CLAUDE.md 관리 블록 갱신:
   - `~/.claude/CLAUDE.md`를 읽는다(없으면 새로 만든다).
   - `<!-- GRANDECLIP:START -->` … `<!-- GRANDECLIP:END -->` 사이 내용을
     `global-security-block.md` 본문으로 **교체**한다. 마커가 없으면 파일
     끝에 마커와 함께 **추가**한다. 마커 밖 개인 내용은 건드리지 않는다.
4. 요약 출력: `링크/복사 N · 건너뜀 N · 충돌 N`과 충돌 목록.

멱등성: 재실행 시 링크는 "이미 있음"으로 건너뛰고, 관리 블록은 추가가 아니라
교체된다 → 몇 번 돌려도 결과가 같다.

### 5.2 파일 방식 분기 (D2)
- **mac/Linux (`globalize.sh`)**: 심볼릭 링크. repo만 최신이면 전역도 따라감.
- **Windows (`globalize.ps1`)**: 복사(`Copy-Item`). 심볼릭 링크는 관리자/개발자
  모드가 필요해 비개발자 환경에서 실패할 수 있어 회피. 복사이므로 repo 갱신
  후에는 재실행이 필요함을 요약에서 안내.

### 5.3 겹침(충돌) 처리
- repo 스킬 중 전역과 이름이 같고 **내용이 다른** 것(현재 `skill-creator`)은
  덮지 않고 충돌로 보고한다.
- 내용이 같은 것(`hook-creator` 등)은 이미 전역에서 동작하므로 건너뛴다.

### 5.4 setup-workspace 흐름 변경 (D1)
Step 5(완료 안내) 뒤에 **Step 6: 전역 적용(선택)** 을 추가한다.

- 안내 문구(비개발자 친화, 예시):
  > "마지막으로 — 방금 만든 설정(편리한 커맨드 + 회사 보안 지침)을 **이
  > 컴퓨터 어디서든** 쓸 수 있게 해드릴까요? 추천해요 🙂 [예 / 아니오]"
- **예** → Claude가 OS를 감지해 알맞은 스크립트를 실행하고, 스크립트 요약을
  친근한 한국어로 전달한다. (예: "✅ 커맨드 7개와 회사 보안 지침을 이 컴퓨터
  전체에 적용했어요. 이제 어느 폴더에서 열어도 그대로 동작해요.")
- **아니오** → "이 설정은 이 워크스페이스 폴더 안에서만 동작합니다. 나중에
  `/setup-workspace`를 다시 실행하면 언제든 전역 적용할 수 있어요."로 종료.
- 사용자는 **Yes/No 한 번**과 요약만 본다. 터미널 조작 노출 없음.

## 6. 보안 지침 단일 원천화 (D5)

현재 보안 텍스트가 workspace CLAUDE.md 템플릿과 전역 CLAUDE.md에 중복돼 있다.
`00-system/03-guides/global-security-block.md`를 유일한 원천으로 삼는다.
- globalize 스크립트는 이 파일을 읽어 전역 CLAUDE.md 관리 블록에 주입한다.
- setup-workspace의 workspace CLAUDE.md 생성 단계도 같은 파일을 참조하도록
  정렬한다(문구 불일치 방지). 회사 정책 변경 시 이 한 파일만 수정한다.

## 7. 에러 처리
- 전역 항목 충돌: 실패가 아니라 **건너뜀 + 보고**. 스크립트는 0으로 종료.
- Windows: 링크 대신 복사이므로 권한 문제를 회피. 실패 시 해당 항목만 보고.
- `~/.claude` 쓰기 불가 등 치명 오류: 명확한 메시지로 중단하고, 사용자에게
  수동 안내 링크(가이드) 제시.

## 8. 테스트 계획
- **mac(현재 환경)**: 스크립트 실행 → 링크 생성 확인 → 재실행이 깨끗한지(멱등)
  확인 → 전역 CLAUDE.md 관리 블록 삽입/교체 확인 → 기존 개인 내용 보존 확인 →
  충돌 항목(`skill-creator`)이 보고되고 덮이지 않는지 확인.
- **Windows**: 실기 테스트 불가. `.ps1`은 `.sh` 로직 미러링, "미검증"으로 표기.
- 회귀: 이번에 수동으로 만든 전역 링크/`~/.claude/CLAUDE.md`가 스크립트 재실행
  으로 동일 상태에 수렴하는지 확인.

## 9. 롤아웃 · 마이그레이션
- 앞선 대화에서 수동으로 만든 전역 링크(brand-guidelines, canvas-design,
  internal-comms, zettelkasten-linker, 커맨드 7개)와 `~/.claude/CLAUDE.md`는
  스크립트가 멱등적으로 흡수한다(같은 링크는 건너뜀, CLAUDE.md는 관리 블록으로
  정규화). 별도 정리 불필요.
- 전역 CLAUDE.md의 `#gc-ai-라운지` 등 조직 전용 문구는 SSOT 파일에 포함되므로
  조직 외 사용 시 그 파일만 조정.

## 10. 미해결 · 후속
- 되돌리기 스크립트(`--unlink`)는 후속 과제.
- 스크립트 위치를 `00-system/02-scripts/`로 신설할지, 기존 `.claude/hooks/`와
  합칠지 — 본 설계는 `00-system/02-scripts/` 신설을 택함(훅이 아니므로).
